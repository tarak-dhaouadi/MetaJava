# Changelog

### Added - "Baujat model" drop-down (Baujat plot no longer hard-wired to the common-effect model)
- New drop-down **Baujat model** (section 10, directly below *Baujat plot*, same look as *Trim-fill model* and *Radial model*): **As the analysis (metafor)** (default) and **Common effect (meta)**.
- *Common effect (meta)*: the plot of meta::baujat as before (contribution to overall heterogeneity, influence on the overall result; common-effect refit without each study).
- *As the analysis (metafor)*: when the random-effects model is selected, the plot of metafor::baujat.rma: x = squared Pearson residual (y_i - mu)^2 / (v_i + tau^2) of the full fit, y = influence on the fitted value (mu - mu_(-i))^2 / var(mu_(-i)); the model (tau^2 estimator, GENQ / GENQM weights, Knapp-Hartung scale factor) is refitted after every deletion. The axes are labelled accordingly. With a common-effect analysis, and for GLMM analyses (not covered by metafor's baujat), both entries give the common-effect plot.
- Applies to both themes (Default, ggplot2 style); the points of each model are computed once per analysis and in parallel. New self-tests compare the random-effects points with an independent DerSimonian-Laird computation and check that the two models differ only for a random-effects analysis.

### Fixed / Added - radial plot follows the random-effects model; new "Radial model" drop-down
- The Default, ggplot2 and STATA radial plots silently used the common-effect model even when the random-effects model was selected; only the metafor style used the analysis model. All four themes now use the same model.
- New drop-down **Radial model** (section 10, directly below *Radial (Galbraith) plot*, same look as *Trim-fill model*): **As the analysis (metafor)** (default; random effects, i.e. tau^2 in the weights, random-effects slope and interval, when the random-effects model is selected, otherwise common effect) or **Common effect (meta)** (always the common-effect model). It applies to every theme.
- With the random-effects model the axes read 1 / sqrt(SE^2 + tau^2) and effect / sqrt(SE^2 + tau^2); the metafor-style arc interval follows the chosen model too.

### Changed - "Avoid label overlap": a label can no longer cover a study symbol (`LabelPlacer` rewritten)
- The old placer was a force simulation: labels were pushed away from the symbols but could still end up on top of them (and leader lines ran through other points). It is replaced by a constraint-based placement. **Hard rules:** a label box keeps at least 2.5 px away from every symbol of the plot (its own, the other studies', unlabelled ones, the PET and PEESE squares at SE = 0), never overlaps another label and never covers a legend or text drawn later on the plot (L'Abbe legend, LFK index of the Doi plot, trim-and-fill legend of the MetaWin funnel). Symbols are measured at their real extent (star, triangle, diamond and square symbols of the regression plots reach beyond their nominal radius). Distance to the point and leader lines are what is traded for these rules.
- Among the admissible places the placer takes the one that keeps the label close to its study. Order of priorities: (1) no label on a symbol or on another label; (2) no leader line through a symbol it could avoid; (3) no leader line through a label or across another leader line; (4) short distance. Each priority outweighs all the ones below it, so the search cannot trade a symbol crossing for fewer leader-leader crossings. The leader is drawn from the edge of the symbol to the nearest point of the box. Method: candidate places on rings around each symbol, greedy placement (most crowded first), re-placement and exchange of pairs of labels, then simulated annealing in four independent chains.
- Leader through symbol: where bubbles overlap, a leader that starts inside a neighbouring bubble must cross it, so that crossing is counted as unavoidable and costs only for the part beyond the shortest way out; the rest of a leader is priced as an avoidable crossing (grazing within 1 px at half price). Result on the "Binary outcome" example (60 plots, RR and OR): 5 leaders cross a symbol they could avoid (OR bubble / adjusted plots, one each), 42 cross one only at an overlapping origin.
- A label with no free place near its study moves as far as needed (any free spot of the panel); only when a plot is so crowded that the labels cannot all fit do labels overlap each other, never a symbol. There is no cap on the number of labels or iterations and no clock: the search ends when a further round no longer reduces the number of conflicts, so the result is the same on every machine, at every export scale and at any number of CPU threads (four chains, results combined in a fixed order); the chains and the candidate precomputation run in parallel.
- Leader-leader crossings are minimised, not excluded: the 60 example plots have 24 crossings among 476 leader lines; layouts that are geometrically hopeless (coincident or tightly clustered symbols) can keep some. Measured on the revised implementation (2 CPU cores): typical, the 60 "Binary outcome" plots with 23 labels: median 87 ms, 90% under 0.9 s, slowest 3.1 s (bubble plots with large star symbols); large, 90 / 150 uniformly scattered studies: 1.2 s / 6.9 s; dense, 60 clustered studies: 12 s (79 crossings); degenerate, 40 coincident symbols: 18 s; 100 studies packed into a few clusters: 5 s (many unavoidable crossings). Time grows with crowding rather than with the number of labels, and shrinks with more CPU cores.
- Applies to every plot with the option: bubble and adjusted regression plots (all symbols), funnel plots and funnel of precision (Default, MetaWin, STATA, trim-and-fill), asymmetry-test plot, Doi, PET-PEESE, radial (all themes), L'Abbe (both themes) and the ggplot2-style Baujat plot. New test `LabelPlacerTest` (run by `build.sh --test`) renders all of them on the "Binary outcome" example (RR and OR) and on synthetic stress cases and checks the rules geometrically.

### Fixed - exact permutation test: the time estimate was off by a factor of about 3 (7 min estimated, 20 min needed)
- **Cause:** the estimate was extrapolated from 5 to 25 timed fits of **one thread** right after a short warm-up, multiplied by the number of permutations and divided by the number of threads. The JIT compiler was still warming up (the same model gave 10 us, 6 us and 5 us per fit on three successive estimates, against 2.3 us once warm), thread scaling was assumed to be perfect, and the serial part (permutation generator, tally) was ignored. The estimate could therefore be much too low or much too high; either way the budget decision was unreliable.
- **Now:** the estimate is the measured throughput of the **real parallel loop** (random arrangements fitted through `Par.forRange` with the configured number of threads, so thread scaling, allocation and garbage collection are included), repeated in rounds for at least one second and until two successive rounds agree within 10 %, plus the measured cost of the serial generator. On the test models the estimate is within about 10-25 % of the actual time (slightly too high rather than too low). The output states the measured fits per second.
- **Safety factor (default 1.25, configurable):** the measured time is multiplied by a safety factor before it is compared with the time budget, so the decision errs on the side of refusing. Set it with `-Dmetajava.exactSafety=F` (1 to 100; 1 = no margin; invalid values fall back to 1.25) or through `Perm.run(..., exactBudgetSeconds, safetyFactor)` / `Perm.plan(..., budgetSeconds, safetyFactor)`. The same conservative number is used for the budget check, the refusal message and the result header; the plan also keeps the unadjusted `measuredSeconds`. It is a conservative estimate, **not a guarantee** that the test finishes within the budget (throttling, background load); a real hard timeout is a separate feature.
- The output of a finished exact test now reports "Computing time: ... (estimated beforehand: ...)".
- The progress bar of an exact test shows one overall fraction instead of restarting for every chunk of 20 000 permutations (`Par.progressSink()`).

### Changed - exact permutation test: exact count known up front, no int limit, honest refusal when infeasible
- **Exact count before anything is generated:** `Perm.plan(...)` computes the number of unique permutations k!/(n1! n2! ...) with arbitrary precision (`BigInteger`), the group sizes of identical model-matrix rows, metafor's double-precision count for comparison (it overflows to Infinity from about k = 171 distinct rows, e.g. "Too many iterations required for an exact permutation test."), and the exact-or-random decision, in milliseconds. The count is printed in the output ("all N unique permutations").
- **No artificial limit:** the previous guard "Number of iterations requested too large." was an `int`-range check on the permutation count (the exact test never allocated arrays of that size: it enumerates in chunks of 20 000 with an incremental next-permutation generator, O(chunk x k) memory; an exact test of 184 756 permutations runs in a 48 MB heap). The count and the loop now use `long`.
- **Infeasible exact tests are refused, not approximated:** an exact test is not run when it has more than 2^63 - 1 permutations or is estimated, from timed permuted fits of the model, to need longer than the time budget (default 600 s, `-Dmetajava.exactBudget=SECONDS`; not a limit on k). `Perm.InfeasibleExactTest` (an `IllegalArgumentException`, shown in the output panel) gives the count, group sizes, time per fit, estimated time and the reason, states that it is a limit of time and not of memory, and offers a random test with a number of permutations of your choice, labelled as a random test. An exact test needing at most `iter` fits is always run.
- Tests (1026 in all): exact counts by formula, by incremental enumeration and by metafor's formula; C(200,100) without overflow; 180! against metafor's Infinity; a 3-level factor against a brute force over all 8! permutations; the refusal message and plan; the random alternative labelled as random.

### Documented - ML, REML and EB solve the estimating equation exactly (deliberate difference from metafor)
- tau² of the ML, REML and EB (= PM) estimators is the root of the estimating equation, found to 1e-12 (Brent). metafor iterates Fisher scoring and stops when the change in tau² is <= 1e-5 (`control = list(threshold = 1e-5)`), so its tau² can be off by a few 1e-6 (e.g. 0.02448828 against the exact 0.02448478; the REML score is 2.6e-3 at metafor's value and 1e-11 at the exact one). t, F, QM and the Knapp-Hartung scale factor inherit that difference (about 1e-5 relative); the permutation p-values were identical in the check against metafor 4.6-0. Numerical accuracy is preferred over reproducing metafor's stopping point; `rma(..., control = list(threshold = 1e-12))` in R reproduces MetaJava's values. A self-test now checks that the REML score is zero to full precision.

### Fixed - random permutation test: metafor's redraw-until-valid rule, observed fit as first of `iter`, R's random numbers
- **Failed permuted fits are redrawn** (`permutest.rma.uni`, approximate test: `while (i <= X.iter) { res <- try(rma.uni(...)); if (inherits(res, "try-error")) next; ... }`). Before, a permutation whose refit stopped with an error was dropped, so fewer than `iter` valid fits remained. Now fits are drawn until `iter` valid ones exist; the exact test is unchanged (a failed permutation leaves its slot undefined, as metafor's NA).
- **The observed fit is the first of the `iter` permutations** (`beta.perm[1,] <- x$beta; zval.perm[1,] <- x$zval; QM.perm[1] <- x$QM`). So `iter - 1` permutations are random and p = hits / `iter` (smallest p = 1 / `iter`); before, `iter` random permutations plus the observed one gave p = (r + 1) / (`iter` + 1). The first valid permuted fit is drawn and fitted (it decides which later draws are used) but its statistics are replaced by the observed ones, as in metafor.
- **Permutations are drawn as in R:** a port of R's Mersenne Twister, `set.seed` scrambling and `sample(k)` (rejection sampling, R >= 3.6) from the rows of the model matrix sorted as metafor sorts them, so an integer seed gives the permutations metafor draws after `set.seed(seed)`. Random p-values for a given seed therefore changed (they are statistically equivalent); they do not depend on the number of threads or on which fits fail.
- **Retries are not limited, as in metafor:** a failed permuted fit is redrawn until `iter` valid fits exist, however many draws that takes; the analysis stays cancellable. `Perm.run(..., maxDraws)` can still set a limit; when it is reached the test stops with a message giving the number of valid fits, draws, failed fits and the first error.
- **Exact or random is decided as metafor does (`X.exact.iter`):** by the number of *unique* permutations of the rows of the model matrix, k!/(n1! n2! ...) for groups of identical rows (e.g. 252 for a binary moderator with 5 + 5 studies), compared with `iter`; the exact test enumerates them all when requested or when their number does not exceed `iter`. Before, k! was used and the exact test was limited to k <= 9, so a binary moderator with k = 10 was random in MetaJava and exact in metafor. A request for an exact test that needs too many permutations stops with metafor's messages ("Number of iterations requested too large." / "Too many iterations required for an exact permutation test."). The unique permutations are enumerated in chunks, so memory does not grow with their number. The p-values equal those over all k! permutations (checked by brute force).
- **GENQ / GENQM with zero weights:** a fit whose weighted design matrix X'AX is singular now stops with "Singular design matrix" (metafor: `qr.solve` error) instead of an internal null-pointer error; this is what makes some permuted fits fail when zero weights leave a moderator without variation.
- The output header names the first-slot rule and the new smallest possible p; a note reports redrawn fits. New self-test checks (1005 in all): R's generator against known `set.seed()` output, a sequential re-implementation of metafor's loop as reference (with and without failing fits), the optional limit on the draws, the exact test with failing permutations, the unique-permutation rule (brute-force check, k = 10 binary, refusal of 25!), thread independence. `docs/permutest-parity.R` reproduces the scenario in metafor.

### Fixed - two remaining deviations from metafor (Knapp-Hartung)
- **Common-effect analysis with Hartung-Knapp (Thompson (metafor)):** the fixed-effects meta-regression now applies the Knapp-Hartung test when HK is selected, as `rma(method = "FE", test = "knha")` does (before: Wald z), and the output carries metafor's warning "Knapp and Hartung method is not meant to be used in the context of FE models." (a `warning` line in the Details).
- **Permutation test with undefined statistics:** as `permutest.rma.uni`, each statistic now removes its own undefined (NA) permutations (`na.rm = TRUE`) and an undefined observed statistic gives NA, instead of dropping a whole permutation when any statistic was undefined. With all effects equal the omnibus p-value is NA (before: 1.0), an infinite z counts as a hit when it equals the observed one (Inf >= Inf), and an undefined coefficient statistic gives NA.
- **All effects equal:** when the Knapp-Hartung residual sum of squares is at machine epsilon the scale factor is 0, as in metafor (before: 0/(k-p) rounding noise); with the ad hoc option "se" it is then floored at 1. Applies to the meta-regression, its permutation test and Thompson (metafor); the influence diagnostics already did this.

The meta-regression (and its permutation test) and the metafor funnel-plot tests apply exactly that; meta's options "ci" and "IQWiG6" (rules based on the width of the pooled-effect CI, so undefined for a regression coefficient) have no metafor counterpart and give the plain Knapp-Hartung test (`test = "knha"`). ### Fixed - three deviations from metafor (found when checking the metafor tests and the PL interval)
- **PL interval of a GENQ / GENQM fit with weights:** metafor refits the model with the same weights, so its log-likelihood uses the weighted coefficient (not the ML one) at every tau². `Rma.logLik(..., weighted)` now does the same for the profile-likelihood interval (e.g. 0.0132 to 0.3249 instead of 0.0029 to 0.3147 on the test data); the second-maximum diagnostic `higherMode()` keeps the true likelihood, and fits without weights are unchanged.
- **Thompson (metafor) after a common-effect-only analysis:** metafor fits the regtest model with the method of the analysed model, so a common-effect analysis gives a fixed-effects meta-regression (tau² = 0, Wald z-test, no Knapp-Hartung). MetaJava used the selected tau² estimator; the report now names the fixed-effects model.
- **Ad hoc Knapp-Hartung in Thompson (metafor):** only the option "se" (metafor test = "adhoc") sets the scale factor to at least 1, as in the meta-regression; meta's "ci" has no metafor counterpart and gives the plain Knapp-Hartung test.

### Changed - safer parallel analysis (no change in any result)
- **Memory-hungry sections no longer all start together.** GOSH, leave-one-out, influence and the other heavy sections of a run are started in the same order as before, but at most `Par.heavyLimit()` at a time (one per 400 MB of maximum heap, between 1 and the number of threads; override with `-Dmetajava.heavy=N`). The next one is submitted when a running one finishes, so no pool thread waits for a permit; the small sections are not limited. (A 500 000-subset GOSH with 40 studies needed less than 256 MB; the limit is a safety margin for larger data sets and small heaps.)
- **Baujat points:** the lock is now per analysis (it was one lock for the whole program, held during a parallel loop), so Baujat plots of other analyses (subgroups) are no longer held up; the points and labels are volatile fields, labels stored first.
- **`Plots.lastForestAxis`** (read only by the axis tests) is now thread-local (`Plots.lastForestAxis()`): forest plots are rendered in parallel and a shared field could show the axis of another plot.
- **Self-test:** new checks that the summary (with the tau² sensitivity table), the Baujat plot and the GOSH estimates and clusters are identical on 1 and on the maximum number of threads, and that `Par.submitLimited` runs every task, returns the results in order and never exceeds its limit.

### Changed - faster GOSH cluster detection (no change in any result)
- The cluster detection was entirely single-threaded and took 1-4 s per GOSH analysis (ordinary and meta-regression), after every change of a setting. It now runs on the worker pool: the 18 EM fits of the Gaussian mixture (1 to 6 components, 3 starts each) run in parallel, and inside each fit the E step (over subsets), the M step (over components) and the assignment of every subset to its cluster do too; the silhouette widths of the separation check (one point per task) are computed in parallel as well.
- The random stream is unchanged: the k-means++ starting centres are drawn one after the other from the seeded generator exactly as before, the fits are then compared in the original order, and every sum is accumulated in its original order. Clusters, silhouette widths, ICL / BIC, inclusion rates and the report are therefore bit-for-bit identical to the previous version and to a single-threaded run (checked on ordinary and meta-regression GOSH, 8 000 and 200 000 subsets, 1 and 4 threads).
- The silhouette width over the combined space that was computed in every merge round of the separation check but overwritten before being read is no longer computed.

### Changed - faster analysis when many analyses are selected (no change in any result)
- All sections of a run (subgroups, leave-one-out, cumulative, influence, GOSH, selection model, Drapery report, ...) are now started together in the shared worker pool, heaviest first, instead of the heavy ones running one after another. The output keeps the order of the sections.
- The plots of a section are rendered in parallel; the GOSH meta-regression runs at the same time as the ordinary GOSH (its output stays right below it).
- The 14 refits of the "Sensitivity analysis by tau^2 estimator" table run in parallel and are assembled in the original order.
- Progress is computed from all running sections. Output text, tables and plots are identical to the previous version (checked section by section, with 1 to 16 threads).

### Added - metafor's other tau² interval types: PL, HT, Wald, Wald.log, Wald.sqrt
- The "CI of tau²" list now has the remaining `confint.rma.uni(type = ...)` types of metafor 4.6-0, computed for the model fitted with the selected estimator, so they differ between estimators (the Q-profile interval is a property of the data and is the same for REML, ML, EB, PM, PMM, HE, HS, SJ, ...; DL keeps the Jackson default of meta; GENQ / GENQM keep the generalised Q-statistic interval).
- PL: profile likelihood (REML likelihood for REML, ML likelihood for every other estimator), tau² fixed on [tau2.min, tau2] and [tau2, tau2.max], objective qchisq(1 - alpha, 1), uniroot tolerance eps^0.25. Wald: tau² +- z se.tau2 (lower bound at 0); Wald.log and Wald.sqrt: the log and square-root versions (tau² = 0 gives NA for the upper bound of Wald.log, as in R). HT: Higgins-Thompson interval for H² transformed to tau² (no moderators, k > 2). All use the se.tau2 of the estimator.
- The defaults are unchanged (metafor: QP, GENQ for GENQ / GENQM).
- The report marks a limit that reached the search range with ">" (PL: tau2.max = max(100, 10 tau²)), shows NA for limits metafor returns as NA, and names the interval used. PL is accurate to metafor's uniroot tolerance (eps^0.25; error of the limits below 4e-5 in 2100 test fits).

### Investigated - leave-one-out studentized residual (rstudent): the normal reference is liberal when tau^2 > 0 (no change to any number)
- **Question.** In the earlier meta-regression GOSH simulation the studentized residual (leave-one-out, REML) flagged at least one study in 8-63% of the data sets that had heterogeneity but no planted outlier. This was investigated separately from the clustering, which is unchanged.
- **What the app does.** `rstudent` is shown in the table and plot but is **not** a flagging rule: only dffits, Cook's distance, hat and DFBETAS flag a study (as in metafor::influence). The dotted +/-1.96 lines in the plot are unadjusted per-study limits. The 8-63% figures come from the simulation's own rule "any study beyond the normal Bonferroni limit". Intended family-wise error rate of that rule: 5% over the k studies, i.e. |z| > qnorm(1 - 0.025/k).
- **Method** (`docs/simulations/Sim5_studentized_residuals.java`, 1500 data sets per scenario, no outlier, REML, k = 12 / 20 / 30, standard errors 0.08-0.33, ordinary random-effects model and meta-regression with one covariate). Besides the app's `rstudent`, an *oracle* residual with the true tau^2 and true variances was computed, and a t-based Bonferroni limit (k-p-1 df).
- **Results** (empirical, for these scenarios; ordinary / meta-regression; share of studies beyond 1.96, then share of data sets with at least one study beyond the normal Bonferroni limit, beyond the t Bonferroni limit, and the same for the oracle):

| scenario | per study > 1.96 (nominal 5%) | SD of rstudent | any > normal Bonferroni (nominal 5%) | any > t Bonferroni | oracle: per study / any > normal Bonferroni |
|---|---|---|---|---|---|
| homogeneous, k = 12-30 | 4.2-4.5 / 3.8-4.4% | 0.95-0.97 | 4 / 4% | 0-1 / 0-1% | 5% / 5-6% |
| tau = 0.2-0.5, k = 12 | 7.7-8.3% | 1.11-1.14 | **18-23%** | 2-6% | 4.7-5.3% / 4-5% |
| tau = 0.2-0.5, k = 20 | 6.5-6.9% | 1.06-1.07 | **15-18%** | 5-7% | 4.8-5.2% / 5-6% |
| tau = 0.2-0.5, k = 30 | 6.0-6.1% | 1.04 | **12-14%** | 5-6% | 5.0-5.2% / 4-5% |
| tau = 0.3, k = 20, equal standard errors | 6.6 / 6.8% | 1.06-1.07 | 13 / 16% | 5 / 5% | 5% / 4-5% |
| skewed random effects, tau = 0.3 / 0.5, k = 20 | 6.7-7.1% | 1.13-1.17 | **38-41 / 50%** | 22-27 / 32-34% | 4.8-5.0% / **19-25%** |

- **Findings.** (1) *Cause 1, heterogeneity with normal random effects:* the oracle residual is calibrated (about 5% per study, 4-6% family-wise) in every scenario, so the leave-one-out residual itself is a sound standardisation; the excess comes from using the estimate of tau^2 as if it were known. The leave-one-out REML estimate is on average too small (median tau^2.del / tau^2 = 0.82-0.98, lowest at k = 12) and its sampling variation is ignored, so the residuals are over-dispersed (SD 1.04-1.14) and the tails are heavier than normal. The inflation is largest for few studies (k = 12) and shrinks with k. (2) *Homogeneous data:* the normal reference is conservative (about 4% per study, 0-1% with the t limit), because tau^2.del is exactly 0 in more than half of the fits. (3) *Cause 2, skewed random effects:* a different mechanism: the oracle per-study rate is still 5%, but the family-wise rate is 19-25% even with the true tau^2, so the normal tail is wrong for non-normal random effects; neither the t limit nor a better tau^2 repairs this. (4) The setting is the same in the ordinary model and in the meta-regression with one covariate (no systematic difference), and not related to the number of leave-one-out fits failing (none excluded). (5) The scenarios that produce the earlier 8-63% range are the heterogeneous ones (normal reference) and the skewed ones; the homogeneous ones give about 4%.
- **Is the normal Bonferroni reference appropriate?** Not as a 5% family-wise limit when tau^2 > 0: in these scenarios it gave 12-23% (normal random effects) and 38-50% (skewed random effects). A t reference with k-p-1 degrees of freedom brought the family-wise rate to about 2-7% for normal random effects, but it is an empirical improvement for these scenarios, not a theoretical result, and it does not help for skewed random effects.
- **Decision.** No diagnostic, estimate or flagging rule is changed: `rstudent` reproduces metafor and does not flag anything. What changed: the influence report now carries a note (`Report.influenceText`) that rstudent is not a flagging rule, that +/-1.96 are unadjusted per-study limits, and the empirical inflation found here; a self-test checks the note. The earlier GOSH simulation entries below were reworded as empirical results of the tested scenarios, with the imprecision of 24 data sets per scenario stated, and the README and the `GoshCluster` Javadoc no longer read as performance guarantees. ### Simulation results - meta-regression GOSH cluster detection (empirical results of the tested scenarios; no change to the implementation)
- **How to read these numbers.** They are empirical rates observed in the simulated scenarios listed here, not general performance guarantees. With 24 data sets per scenario each rate is imprecise (an observed 50% has a 95% interval of roughly 31-69%, an observed 4% of roughly 1-20%), so differences of 10-20 percentage points between scenarios or between thresholds are within noise. Other designs (other numbers of studies, effect sizes, standard errors, covariates, non-normal random effects) can behave differently. The Bonferroni limit in the last column is the normal one, which the entry on studentized residuals above shows to be liberal when tau^2 > 0, so that column is, if anything, optimistic.
- **Design.** Meta-regression GOSH (intercept + one covariate with a true slope of 0.3), 24 random data sets per scenario, 3000 random subsets, standard errors 0.08-0.33 (one scenario 0.10-0.25). The table gives the share of data sets in which: clusters were reported; the planted outlier was among the studies that separate the clusters; the study-level studentized residual (leave-one-out, REML) flagged the planted study at |z| > 1.96 and beyond a Bonferroni limit.

| scenario | clusters reported | planted study separates | clusters but planted study not separating | planted |rstudent| > 1.96 / Bonferroni |
|---|---|---|---|---|
| homogeneous, k = 12 / 20 | 0 / 0% | - | - | - |
| tau = 0.2, k = 12 / 20 / 30 | 0 / 0 / 0% | - | - | - |
| tau = 0.3, k = 12 / 20 / 30 | **13** / 0 / 0% | - | - | - |
| tau = 0.5, k = 20 / 30 | 0 / 0% | - | - | - |
| skewed random effects tau = 0.3 / 0.5, k = 20 | 4 / 13% | - | - | - |
| one outlier +0.75 / +1.0 / +1.5 / +2.0 / +3.0 | 17 / 29 / 42 / **96** / 100% | same | 0% | 92-100% / 71-100% |
| one outlier -1.5 / -3.0 | 50 / 100% | same | 0% | 100% / 96-100% |
| one outlier +1.5 / +3.0 at the highest-leverage covariate value | 46 / 96% | same | 0% | 100% / 100% |
| two outliers same direction +1.5 / +2.5 / -1.5 | 63 / 92 / 67% | same | 0% | 100% / 75-100% |
| two outliers opposite directions +/-1.5 / +/-2.5 | 46 / 92% | same | 0% | 100% / 96-100% |
| one outlier +2 with tau = 0.2 / two outliers +2 with tau = 0.2 | 67 / 38% | same | 0% | 100% / 92-100% |

- **Findings.** (1) False clusters: 0-4% in most heterogeneous data sets without outliers, 13% at tau = 0.3 with 12 studies and for strongly skewed random effects (tau = 0.5). (2) Detection depends on the size of the shift against the spread of the subsets: ~96% from +2 for one outlier, ~40-60% around +1.5, ~20-30% at +0.75-1.0; it is similar for positive and negative shifts, for one or two outliers, for same or opposite directions and for high or ordinary covariate values (no systematic bias), and it falls when tau^2 > 0 adds spread. (3) Whenever clusters were reported, the planted outlier was among the separating studies (0 cases of a cluster without the planted study). (4) A cluster is a statement about subsets, not about a study: the study-level studentized residual flags a moderate planted outlier far more often than the clusters do, but it also flags some study in 8-63% of the data sets with heterogeneity and no outlier (normal Bonferroni limit; that limit is not a calibrated 5% family-wise limit, see the entry on studentized residuals above), so neither is evidence on its own. The modest sensitivity is the limit of the method (a cluster exists only if the shift stands out of the cloud), not an implementation defect: the implementation is kept.
- The report now states that a cluster shows outlying subsets, not that a particular study is an outlier, and points to the study-level diagnostics for evidence about a study.
- New self-tests for the labelled silhouette values (per cluster adjusted = better of effects and heterogeneity minus 0.10, real heterogeneity value above the adjusted score for the heterogeneity route, labels in the note and the report).

### Changed - cluster detection: fewer false clusters, thresholds checked on simulated data
- **Why.** Taking the better of two silhouette widths (effects, or ln(Q_E/df)) gives every cluster two chances to pass. With the same threshold for both (0.60) the detector reported clusters in 4-21% of data sets that have heterogeneity but no outlier (homogeneous: 0-8%).
- **What.** The two routes now have separate thresholds: effects silhouette >= 0.60 (`MIN_SILHOUETTE`), or ln(Q_E/df) silhouette >= **0.70** (`HET_MIN_SILHOUETTE`, new) with a minimum share of 5% of the subsets (`HET_MIN_SHARE`, new). `detectClusters(minSil, hetMinSil, hetMinShare)` sets them; the result records them. The estimates, subsets, sampling and all other numbers are unchanged.
- **Simulation** (empirical results of these scenarios, not guarantees; 24 data sets per scenario, so each rate is imprecise, roughly +/- 20 percentage points; 3000 random subsets, k = 12-25, standard errors 0.08-0.33; the share of data sets in which clusters were reported; "ordinary / meta-regression" GOSH):

| scenario | route threshold 0.60 | **0.70** | 0.80 | effects route only |
|---|---|---|---|---|
| homogeneous, k = 20 | 0 / 8% | **0 / 4%** | 0 / 4% | 0 / 0% |
| tau = 0.15, k = 15 | 8 / 4% | **0 / 0%** | 0 / 0% | 0 / 0% |
| tau = 0.3, k = 15 | 4 / 17% | **0 / 0%** | 0 / 0% | 0 / 0% |
| tau = 0.5, k = 25 | 21 / 4% | **0 / 0%** | 0 / 0% | 0 / 0% |
| skewed random effects, tau = 0.3 | 13 / 13% | **8 / 4%** | 8 / 0% | 4 / 0% |
| one outlier, +1.0 | 63 / 50% | **58 / 29%** | 42 / 8% | 13 / 0% |
| one outlier, +2.5 | 100 / 100% | **100 / 96%** | 100 / 92% | 92 / 0% |
| two outliers, +2 | 96 / 96% | **92 / 88%** | 75 / 38% | 0 / 0% |
| subgroup of 3 of 12, +0.8 | 54 / 25% | **42 / 17%** | 21 / 13% | 0 / 4% |
| subgroup of 3 of 12, +1.2 | 75 / 46% | **75 / 46%** | 58 / 8% | 0 / 0% |
| subgroup of 4 of 16, +1.0 | 58 / 33% | **58 / 21%** | 33 / 4% | 0 / 0% |

  0.70 removes nearly all the false clusters and keeps most of the power; 0.80 loses too much power (a minimum share of 10% changed nothing, so the default stays 5%). Weak signals are missed (an outlier of +1.0 is found in 58% / 29% of the data sets, a subgroup of +0.8 in 42% / 17%), and skewed random effects still give about 4-8% false clusters in the ordinary GOSH: the clusters are exploratory.
- **Self-tests** now use several data sets per scenario, with weaker signals than before: heterogeneity without outliers (tau = 0.3 and 0.5) gives at most 1 of 6 data sets with clusters, two outliers of +2 are found in at least 4 of 6, one outlier of +2.5 in at least 5 of 6 (ordinary and meta-regression), and the lenient route is shown to give at least as many false clusters.
- Fixed the `detectClusters` Javadoc (it said the check used the effects only), removed the unused `copyHead()` from `GoshCluster`, and fixed the class comment.

### Changed - REML / ML: a second maximum of the likelihood is reported, the estimates are not changed
- **Investigation.** The tau^2 of ML and REML is the root of the score equation found by a search from 0. Checked against a dense grid on the restricted likelihood in 3000 random data sets (3-40 studies, 1-3 coefficients, equal and very unequal variances, outliers, near-equal variances): in 2 of 3000 (7 studies with variances from 0.003 to 16) the likelihood has two maxima and the search stops at the lower one (tau^2 = 3.28, while tau^2 = 0.0038 has a log-likelihood 0.31 higher).
- **Decision.** Moving the estimate to the global maximum changed the metafor reference values of the self-tests (exact permutation p-values in the 4th decimal; GOSH meta-regression means), so the estimates are **left as they are**: they reproduce metafor. The estimator code and the GOSH calculations are untouched (the diagnostic only adds code; no line of `estimateTau2`, `Rma.fit` or GOSH was changed for it). Any change of the estimate needs a separate comparison against metafor.
- **Diagnostic `Rma.higherMode()`** (ML and REML only; sets `higherModeGain`). It evaluates the *same* (restricted) log-likelihood that the score equation is the derivative of, over the whole admissible range tau^2 >= 0: tau^2 = 0 and 240 geometric points from 1e-9 to 1e9 times the scale of the data. Each local maximum of that grid is refined on the score equation (or taken as the boundary 0 when the score is not positive there) and a mode is reported only if its log-likelihood is higher than that of the estimate by more than 1e-6 and its tau^2 differs from the estimate. It is not run for the GOSH subsets.
- **Warning text.** "Note: the restricted log-likelihood has a second, higher maximum at tau^2 = ... (higher by ...). The results above and below use the selected mode, tau^2 = ... (the one found by the usual search from zero, as in metafor); the higher mode is not used in any calculation." It appears in the heterogeneity block of the pooled analysis and in the meta-regression output.
- **Verification** (independent code, not the diagnostic itself): (1) the finite-difference derivative of the likelihood equals the score used by the solver (largest relative difference 2e-5 over 72 000 points, i.e. finite-difference error), so both look at the same likelihood; (2) 16 000 random data sets x REML and ML (3-40 studies, 1-3 coefficients, equal and very unequal variances over up to 6 orders of magnitude, outliers) were compared with a separate 3000-point grid: REML 9 higher modes found, ML 94, **0 false alarms and 0 missed** in both; the smallest reported gain was 0.0002 (so the 1e-6 threshold is not borderline). ML has a second mode about ten times as often as REML.
- Self-tests: the 7-study data set above (estimate unchanged, higher mode 0.0038 found, gain 0.31, both modes stationary and the higher one a maximum, warning states the selected mode and that the higher mode is not used), no warning for ordinary data sets, the reference data and a tau^2 = 0 boundary case, nothing reported for DL / PM; ML reports only clearly higher modes.

### New - permutation test for meta-regression (`permutest`)

The symbol area now follows the inverse variance of the study estimate when the method gives no weights, and a note says so. The other methods are unchanged. Covered by a self-test for IV, Peto, MH, SSW, GLMM and LRP.

### Export - TIFF and JPG
- **Plot format** now offers PNG, **TIFF**, **JPG**, SVG and PDF, both for *Save all plots* and in the type list of *Save this plot* (`.tif` / `.jpg`; typed `.tiff` / `.jpeg` are accepted).
- **Plot resolution (dpi)** applies to PNG, TIFF and JPG (greyed out for SVG/PDF). The pixel size follows the dpi (96 dpi = 1x) and the resolution is recorded in the file (PNG pHYs, TIFF XResolution, JPEG JFIF density), so journals and Word/Photoshop read the right dpi.
- TIFF is lossless (LZW compression, ~3x larger than PNG at most); JPG uses quality 0.95 (lossy, not advised for line art). TIFF needs Java 9 or later (the build targets Java 11).

### Export - SVG and PDF next to PNG, at the chosen resolution
- New **Plot format** selector (PNG / SVG / PDF) in the Export section; it applies to *Save all plots* and is the default of *Save this plot* (the save dialog also offers the three types, and the file extension wins).
- SVG and PDF are produced by the very same drawing code as the PNG (the plots draw into a recording `Graphics2D`, `VectorGraphics`), so layout, line widths, dashes, grey levels and text positions are identical, for every plot including the forest plots.
- **Resolution.** *Plot resolution (dpi)* applies to PNG only (the spinner is disabled for SVG/PDF). Vector files are resolution independent and are written at the plot's natural size (scale 1: e.g. 620 x 520 px for the Doi plot; PDF 1 px = 0.75 pt, i.e. 465 x 390 pt), so a high dpi setting no longer produces huge pages (Acrobat refuses pages above 14 400 pt).
- SVG keeps live text (`<text>`, with `textLength` so the layout survives font substitution); PDF writes text as glyph outlines (no font embedding, same look everywhere, not selectable). Pages are white, as in the PNG.
- Both carry the plot title: `<title>` in the SVG, document information (Title, Creator, Producer) in the PDF.
- Checked by rasterising the PDFs and rendering the SVGs in Chromium, then comparing with the PNG (L'Abbe, Doi, Baujat for RR, OR, RD, ASD: mean grey difference below 1 of 255).

### Publication bias - Doi plot and LFK index
- New option **Doi plot and LFK index**: |Z-score| (reversed axis) against the effect size, studies joined in order of effect, LFK index printed in the plot, optional dashed line through the apex (smallest |Z|; checkbox **Mark the apex**, off by default because `metasens::doiplot` does not draw it), plus a table (effect, SE, Z, |Z|) and the interpretation (|LFK| <= 1 no, <= 2 minor, > 2 major asymmetry).
- The index follows `metasens::lfkindex` exactly (precision-weighted mid-ranks, N = 100 max(var) / var, percentile = (MidRank - 0.5) / sum(N), index = 5 / (2k) * sum(Z + (maxZ - minZ) / (max - min of TE - TE.apex) * (TE - TE.apex))). Ratio measures are on the log scale with back-transformed axis labels. Fewer than 5 studies: a caution is printed.

### Diagnostics - L'Abbe plot
- New option **L'Abbe plot (binary outcomes)** (metabin): event rate in the experimental group against the control group, symbol area proportional to the weight (common-effect weights if shown, otherwise random-effects), grey no-effect diagonal, dashed lines for the pooled common-effect and random-effects estimates (RR, OR, RD, ASD), study labels optional. Both axes use the same limits, fitted to the data.

### Fix - "Save this plot" type and extension
- Choosing PNG / SVG / PDF in the save dialog now switches the extension of the file name, and the chosen type is what gets written.
- **Bug:** with *Plot format* = PNG, choosing PDF (or SVG) in the dialog could leave the name as `.png`, and the file was then written as PNG. `JFileChooser.setFileFilter` clears the selected file, and some look-and-feels / platforms (seen on Windows with Nimbus) refresh the name field only after the filter event, overwriting the new name.
- **Fix:** new `PlotChooser`. The name is refreshed after the dialog's own update (`invokeLater`), and, independently of what the field shows, the extension is fixed when *Save* is pressed: the selected type decides, unless the user typed another known extension (`fig.svg`). The dialog also asks before replacing an existing file. Covered by self-tests.

### Fix - x-axis labels on log-scale plots with a narrow effect range
- When the 1-2-5 log ticks left fewer than two labels inside the axis (e.g. risk ratios between 0.5 and 0.7), the axis showed none; it now falls back to evenly spaced labels. Affects funnel, Doi and any other plot using the shared axes.

### Forest plots - "Experimental" / "Control" group headings (metabin, metacont, metainc)
- The column headings of two-group outcomes now carry the group labels above them, centred over each group's columns (Events/Total, Total/Mean/SD, Events/Time), as in meta::forest. Applies to the main and subgroup forest plots; the labels are `labelE` / `labelC` of the settings.

### GLMM - tau^2-based I^2 (metafor) shown next to the Q-based I^2 (meta)
- meta and MetaJava derive I^2 and H from the Wald-type Q ((Q - df) / Q); `metafor::rma.glmm` reports I^2 = tau^2 / (tau^2 + vt) with the typical sampling variance vt of the continuity-corrected study estimates (H^2 = 1 / (1 - I^2)). The two definitions differ, so the summary now prints both for random-effects GLMM analyses (all models), e.g. CM.EL, 20 studies: I^2 = 76.7% [64.2%; 84.8%], H = 2.07 [1.67; 2.56] (Q-based) and I^2 = 75.2%, H = 2.01 (tau^2-based, metafor: 75.249%, H^2 = 4.04). The methods block names both definitions. The forest plot keeps the Q-based I^2 (as meta::forest).
- CM.EL Wald-type Q on the 20-study data set: MetaJava 81.44 is the exact value (independent check: 81.4358); metafor / meta print 81.56 because the saturated model is optimised numerically. The likelihood-ratio Q agrees to all printed digits (81.6036). Documented in the self-test as for UM.RS.

### Fix - GLMM UM.RS Wald-type heterogeneity test now equals metafor / meta
- **Problem.** For `model.glmm = "UM.RS"` the Wald-type Q was Cochran's Q on the study log odds (rate) ratios (80-study data set: Q = 325.91, I^2 = 75.8%, H = 2.03), whereas `metafor::rma.glmm` and `meta::metabin` report 296.21 (I^2 = 73.3% [66.8%; 78.6%], H = 1.94 [1.74; 2.16]). Cochran's Q is the correct Wald statistic only for UM.FS.
- **Cause.** metafor computes the UM.RS statistic as the Wald test, on the saturated model (study-specific group effects, common intercept, random study intercepts), that the study-specific effects are equal, with the covariance matrix lme4 reports for its fixed effects. That covariance accounts for the random study intercepts and for the correlation between the study effects through the shared intercept.
- **Fix.** The saturated UM.RS fit now returns its parameters (intercept, sigma, study effects and the modes of the random intercepts); the statistic is computed from the information of the fixed effects with the random intercepts integrated out around their modes (closed form, no extra optimisation). The saturated fit is shared with the likelihood-ratio test, so a full UM.RS fit costs the same as before.
- **Agreement.** 80-study data set: Q = 296.23 against 296.2068 in metafor; the remaining 0.02 is because lme4 stops a little short of the exact saturated-model sigma (Q changes by about 290 per unit of sigma), I^2, H and their CIs agree to the printed digits.
- **Leave-one-out and cumulative** tables now show the UM.RS I^2 derived from this statistic and therefore need the saturated fit (about 20% longer on the 80-study data set). The Baujat plot reads only the common-effect estimate and skips it (`MetaSpec.skipHet`).
- UM.FS, CM.EL, CM.AL, proportions and rates are unchanged.

### Forest plots - compact text below the plot (as meta::forest)
- The heterogeneity line, the tests and the "Details of meta-analysis methods" block now start directly under the last row (e.g. "Prediction interval") instead of always below the x-axis, removing the large vertical gap on the left.
- Each line is checked against the extent of the x-axis, its tick labels and the optional "favours" labels: a line that would overlap them (long lines, wide tick labels such as -0.6 -0.4 ... for correlations, or hazard-ratio axes) is moved below the axis, and so are the lines after it.
- When the heterogeneity / test lines are only slightly too long to fit to the left of the axis (typical for correlations and proportions, whose tick labels start close to the left columns), the plot and the right-hand columns are shifted right by the missing amount (at most 140 px) instead of moving the whole footer below the axis.
- Applies to the main, subgroup, leave-one-out and cumulative forest plots (shared renderer).

### Forest plots - study squares and CI lines now look like meta::forest
- The confidence-interval line and the vertical estimate tick are no longer hidden by the gray square: they are drawn in solid black over it.
- When the whole confidence interval fits inside the square, the horizontal line and the vertical tick are drawn in white (previously nothing was visible).
- Applies to the main, subgroup, leave-one-out and cumulative forest plots (they share one renderer).

### Performance - parallel workflows and background analysis
- New shared worker pool (`Par`): 4 threads by default, capped at the number of cores. Change it with the **CPU threads** spinner in the header (remembered between sessions) or `-Dmetajava.threads=N`.
- Analysis no longer runs on the UI thread. Independent sections (summary/forest, subgroup, regression, leave-one-out, cumulative, funnel, bias test, trim-and-fill, influence, Baujat, radial) are computed in the background, plots are rendered there too, and a busy bar shows progress. A run that has been superseded by a newer setting change is dropped. Saving plots no longer blocks the window.
- Parallelised: leave-one-out, cumulative, influence diagnostics (one leave-one-out refit per study), the NNF prediction-interval bootstrap, the Jackson/BJ matrix construction, and the GLMM per-study likelihood terms.
- Eigenvalues (Jackson/BJ tau^2 confidence interval) now use Householder tridiagonalisation + implicit QL instead of cyclic Jacobi (agrees to ~1e-12, several times faster, more so for large k).
- Leave-one-out and cumulative skip the tau^2 confidence interval (never displayed there) unless I^2 is derived from tau^2.
- NNF bootstrap: the seeded random stream (which depends only on k) is cached; replicates are evaluated in parallel. Results are bit-identical to the single-threaded version.
- Hat values in the influence diagnostics use only the diagonal of the hat matrix (was a full k x k product).
- Results are identical to the previous build irrespective of the number of threads (floating-point summation order is unchanged).

### Performance - UM.RS leave-one-out, cumulative meta-analysis and Baujat plot (80-study data set no longer appears frozen)
- **Cause.** 93% of a UM.RS fit was spent on the saturated model behind the likelihood-ratio heterogeneity test (a Brent search for every study at every Nelder-Mead step, serial), which was computed again in the random-effects fit and in every leave-one-out, cumulative and Baujat refit although none of them displays it. The Baujat plot also ran its refits serially, with the random-effects fit, and again each time it was rendered or saved.
- **Saturated model.** The study effects are now maximised by Newton steps on the analytic score (the routine used for UM.FS, generalised to a profiled study effect), in parallel over studies, started from the previous step; the saturated log-likelihood is computed once and shared by the common-effect and random-effects fits. Boundary maxima (studies with a zero cell) stay confined to the same +/- 15 interval as before.
- **Leave-one-out, cumulative, Baujat.** They skip the likelihood-ratio test (not displayed there); Baujat refits only the common-effect model, in parallel, and keeps its points so that saving the plot does not repeat the work.
- **Progress bar.** It is indeterminate until the first section has finished (a long first section no longer shows a bar stuck at 0%).
- **Results.** Estimates, SEs, tau^2, sigma^2, log-likelihoods and both Q statistics are unchanged (identical to 9 decimals on the regression matrix and on 45 extreme random data sets with zero cells and double-zero studies; at most 5e-15 relative in the likelihood-ratio Q). The Baujat image is identical.
- **Timings (one thread).** Main analysis of the 80-study data set: 13.6 s -> 0.7 s. 20 studies: main analysis 4.5 s -> 0.7 s, leave-one-out 37.2 s -> 4.8 s, cumulative 16.4 s -> 2.1 s, Baujat 36.3 s -> 1.3 s (saving it again: 36.9 s -> 0 s). 80 studies after the change: leave-one-out 97 s, cumulative 39 s, Baujat 34 s on one thread (they scale with the number of worker threads).

### Performance - GLMM (UM.RS, UM.FS, CM.EL, and every binomial model)
- **CM.EL:** the non-central hypergeometric pmf no longer sums all min(n1, n2) + 1 terms with one `exp` each at every evaluation. The maximum is located by bisection (the log-weights are concave) and the weights are generated outwards from it by the exact ratio recurrence, stopping at 3e-20 of the maximum. Cost now grows with the standard deviation instead of with the sample size: k = 40 studies of about 3000 patients, 30.6 s -> 0.32 s on one thread.
- **Binomial arms (UM.RS, UM.FS, CM.AL):** the log binomial coefficient (three `lgamma` calls) is computed once per arm instead of at every evaluation, one `exp` serves both the probability and log(1 + exp(eta)), and `Math.log1p` (a slow software routine) is replaced by an equivalent through `Math.log`. UM.RS, k = 150: 8.0 s -> 1.7 s on one thread.
- **UM.FS (fixed study effects):** the study intercept is no longer found by a Brent search (about 40 evaluations of the marginal likelihood per study and per likelihood evaluation, restarted from scratch every time). It is now maximised by safeguarded Newton steps on the analytic score of the marginal log-likelihood, which differentiates the mode of the random effect, the Laplace scale and every adaptive Gauss-Hermite node (so it is the exact derivative of the likelihood that is maximised, for any nAGQ, and Laplace included). The curvature comes from the secant of the last two scores once available, and the search is bracketed by the sign of the score. Each search starts from the optimum (and the random-effect mode) that the same study had at the previous Nelder-Mead evaluation. On average 1.2 to 3 evaluations per search (the warm start often leaves nothing to do) instead of about 40; the Brent search remains as a fallback if a step is not finite or does not converge (it was never needed in testing). Binomial and Poisson (IRR) arms are both covered. Benchmarks on one thread: 30 UM.FS fits (OR and IRR, k = 8 to 50, nAGQ = 1, 3, 7, sparse data) 5.0 s -> about 0.65 s; 300 realistic datasets (k = 5 to 30, tau 0 to 1, rare events, nAGQ = 1 and 7) 78.7 s -> 9.1 s; 150 random extreme datasets 222 s -> 16.6 s.
- On 300 realistic datasets the log-likelihoods, Q statistics and NaN pattern are identical to the previous build, and the parameters agree to a median of 5e-9 (maximum 9e-7, for the standard error of a random-effects fit close to tau^2 = 0), which is the size of the change the previous build itself shows when only the starting value is changed. Only data with complete separation (an effect running to minus or plus infinity, e.g. all events in one arm) give start-dependent estimates and standard errors, in both builds. The self-test now includes UM.FS regression checks (OR with nAGQ = 7 and 1, IRR; common-effect and random-effects fits).

### Performance - parallel pool refinements
- `Par` now uses a work-stealing `ForkJoinPool`: a loop started inside a pool task (e.g. the GLMM likelihood inside a leave-one-out refit that runs in the pool) is split further and the waiting thread helps, so nested loops use idle threads and cannot deadlock. Previously they ran sequentially.
- Cancellation now reaches inside the parallel loops: `Par.withCancel(...)` attaches the "superseded" condition to the analysis; loops and submitted tasks stop at the next iteration instead of finishing a long GLMM fit.
- `Glmm.gh()` (Gauss-Hermite nodes, read for every study at every likelihood evaluation) is lock-free (`ConcurrentHashMap`), so the threads no longer queue on a lock.
- `Par.threads` is `volatile` instead of read through a `synchronized` getter on every loop.
- Results are unchanged (checked byte for byte on 19 analysis configurations with 4 threads).

### Performance - tau² confidence interval of DerSimonian-Laird (Jackson / generalised-Q)
* The Jackson interval (default CI of tau² with DL) took seconds for k = 3-5 and was slow for larger k. The distribution of the
  generalised Q now uses the Ruben/Farebrother series (the algorithm of `CompQuadForm::farebrother` called by metafor), with Imhof's
  integral as fallback; the eigenproblem is reduced to (k-p)x(k-p) once; the root search needs fewer evaluations and runs both
  bounds concurrently; results are cached; subgroups are pooled in parallel. k = 3: 5 s -> under 1 ms. Results agree with the
  previous version to about 1e-9 (the old integral was truncated for k <= 4).

### Fixed - influence diagnostics now follow metafor 5.2-1 (`influence.rma.uni`, `plot.infl.rma.uni`)
- Influential-study rule (red points / `*`): `|rstudent| > 1.96` is no longer a criterion. Only `|dffits| > 3*sqrt(p/(k-p))`, `pchisq(cook.d, p) > 0.5`, `hat > 3p/k` and any `|dfbs| > 1` flag a study. `rstudent` and `cov.r` are displayed only.
- DFBETAS: the denominator is now `sqrt(s2w * diag(vb.del))`, where `vb.del` is the full-design covariance matrix with `tau2.del` plugged in (all k studies), instead of the leave-one-out model's `vb`.
- Knapp-Hartung (`knha`/`adhoc`) regression models: `s2w` scaling is applied to rstudent, dffits, DFBETAS, Cook's distance and cov.r.
- Studies whose leave-one-out fit fails now show NA (NaN) rather than 0, and are skipped in the plot.
- Common-effect (FE) models are no longer silently refitted with DL for the diagnostics.
- DFFITS threshold no longer clamps `k-p` to 1.
- Plot: added the dotted reference line at `qchisq(0.5, p)` (cook.d) and `k-p` (QE.del); cov.r uses a log y-axis (metafor `logcov=TRUE`).

## 0.1.0

First public release of MetaJava (stand-alone Java edition of the analyses of the R packages meta and metafor).

* **Forest plots** (main, subgroup, leave-one-out, cumulative): the x-axis is centred on the null value
  (1 for ratio measures, 0 for differences and correlations), as in `meta::forest`; single means, proportions and
  rates keep an uncentred axis.
* **Influence diagnostics:** studies flagged as influential/outliers are drawn as red points, as in metafor.
* **Prediction intervals:**
  * *Subgroup prediction interval* now controls the subgroup rows of the subgroup forest plot, independently of the main
    *Prediction interval* option;
  * the prediction interval of the main analysis is printed below the test of heterogeneity;
  * the *Results for subgroups* table has a prediction-interval column on the right;
  * new **PI confidence level** setting (default 95): the chosen level appears in the text output (*Prediction interval (99%)*,
    *99% PI* columns) and in the forest plots.
* **Subgroup analysis section:** new options *Test for effect in subgroup* and *Details of meta-analysis methods*
  (subgroup forest plot); *Subgroup variable* moved here.
* **Meta-regression section:** *Covariates* and *Factors* moved here, with an exclusive *none* entry.
* **Build:** the JAR is compiled for Java 11 (class-file version 55), so that it runs on the Java 11+ stated in the
  README (the previous pre-release JAR had been compiled with Java 21). Maven-style source layout, `build.sh` /
  `build.bat` with a headless `SelfTest`, `pom.xml`, GitHub Actions `check` (Java 11/17/21 on Linux, Windows, macOS)
  and `release` (attaches the JAR to a GitHub Release).
